# C8-D — action-tool reachability: always present, and eviction you can undo

Date: 2026-11-14 · Branch: `task/c8-d-tool-reachability` · Base: `feat/refactor-plan` @ `0425bd48`

## 1. Defect

Tool definitions are capped by a token budget (`TOOL_DEF_BUDGET_*`). The evictor
ranks by eviction tier and then by **schema size**, so an agent under pressure
could lose the tools that let it *act* — create / update / submit work, read its
own ledger, look at its queue, answer a human. Nothing announced the loss: the
model was told nothing about what left the schema, and even if it had noticed, it
had no stated way to get the tool back.

This is "Agent self-knowledge" gap C: **the agent wants to act, cannot, and is not
told why.** The whitelist investigation that opened this card is itself a live
sample of the same gap — a name (`request_user_input`) was copied out of prose
into the intended whitelist and it did not exist in the tool registry.

## 2. Root cause (R1 / R2)

- **R1 (one fact, several writers):** "which tools does this turn need" was
  answered in two places — the selection step (base sets, keyword groups, pack
  branches) and the budget evictor (tier + size). Neither knew about "action",
  so the fact "this tool is required to work" had no single owner.
- **R2 (one invariant, several measurements):** the invariant "a tool the runtime
  tells the model to call must exist" was enforced by hand for a growing list of
  special cases (`end_turn`, `open_right_panel`, lifecycle tools …), each with
  its own comment, none derived from the registry.

Fix direction: **one derived whitelist**, one assertion, and eviction restricted
to tools that can be brought back.

## 3. Design

### 3.1 Whitelist is derived, grouped, and typed

`packages/core/src/capability-packs.ts`

```ts
export const ACTION_TOOL_GROUPS = {
  task:   ['task_create', 'task_update', 'task_submit_review'], // needs a task service
  ledger: ['work_status', 'check_mailbox'],                     // always registered
  human:  ['notify_user', 'request_user_input'],                // schema-injected + protected
} as const;
export const ACTION_TOOL_IDS = [ ...task, ...ledger, ...human ];
```

- `ACTION_TOOL_IDS` is **flattened from the groups** — no second list to drift.
- `ActionToolId` is a literal union, so a *typo'd* name fails `tsc` before any test.
- The seven ids were resolved against the **live tool face** (factories
  `createAgentTaskTools` / `createMailboxTools`, plus ToolSelector's `pushUnique`
  injections), not copied from prose.
- **The face is not the handler registry.** `notify_user`, `request_user_input` and
  `end_turn` have a dispatch branch and a pushed schema but no `registerTool`
  handler. The first draft of this list treated handler-lessness as
  unreachability, and the inconsistency showed up immediately: it kept
  `notify_user` and dropped `request_user_input` although the two are identical in
  every respect. One predicate, one answer — `toolFaceNames()` is that answer.
- `request_user_input` is a first-class member on purpose: when the surface is
  compressed the agent must still be able to say "I am blocked, I need one line of
  authorisation". A face that cannot ask a human is the defect, not an edge case.

### 3.2 Fail-fast assertion (no silent filtering)

```ts
assertActionToolReachability(face, { notWired?: ['task'] })
```

- Throws, naming the missing id and its group.
- Called at the one moment the face is final: `AgentManager`'s two assembly tails
  (`createAgent`, restore path), through `toolFaceNames()` = registered handlers ∪
  eviction-immune ∪ schema-injected. The registry alone under-reports: `notify_user`
  has a dispatch branch and a schema but no `registerTool` handler.
- A deployment with no task service must **declare** `notWired: ['task']`. That is
  a named degradation (greppable, one word), not a filter.

### 3.3 Selection: action tools are not "situational extras"

`ToolSelector.selectTools()` forces `ACTION_TOOL_IDS` into the selection for every
pack except `reflex` (a patrol tick is not a work unit). Work-context lifecycle
tools stay session-gated, so `task_submit_review` still cannot leak into free chat.

### 3.4 Eviction may only take what can come back

When the guard is on, `protectedNames` gains
1. every action tool (tier 0 — never a victim), and
2. every tool with **no handler and no schema-injection entry** — such a tool is
   unreachable for the rest of the turn once evicted, so it is never a legal victim.

### 3.5 The eviction hint is actionable

`formatEvictedToolCatalog()` now states the count, names the tools, and gives the
recovery call with real names:

```
## Deferred Tools (schemas omitted for budget)
Core platform tools (shell/files/tasks/memory) and the action tools (create / update /
submit / work_status / check_mailbox / notify_user) stay LIVE above.
These 18 tool(s) were moved OUT of this turn's schema to stay inside the
tool-definition budget. They are not gone — each one is re-discoverable:
  recover: discover_tools({ name: ["bulk_tool_59", "bulk_tool_58", …] })
Activation is sticky: the schema is back from your next turn. Do not guess a tool you cannot see.
- `bulk_tool_59`: …
```

### 3.6 Single switch

`MARKUS_ACTION_TOOL_GUARD=0` (or `actionToolGuard: false` on `selectTools`) restores
the pre-C8-D behaviour wholesale: no forcing, no protection, no restriction.

### 4.5 A regression found and fixed during the work

The first version called `agent.getTools()` unconditionally in `AgentManager`, and
`packages/core/test/agent-manager-core.test.ts` (which `vi.mock`s the whole Agent
class) went from 50/50 green to almost all red with
`TypeError: agent.getTools is not a function`. Fixed by skipping **only** when the
face is unobservable (a test double with no registry), which is stated in the code
rather than hidden: the check is skipped for "not a real agent", never for "some
ids are missing". After the fix: 62/62 green for that file + this card's suite, and
the full-suite count returns to the base reading.

## 5. Single-source decisions worth recording

- **`request_user_input` IS in the whitelist.** An earlier draft excluded it on the
  ground that `discover_tools` answers `unknown` for it. That reasoning mixed two
  different questions: *discoverability* (can `discover_tools` activate it?) and
  *reachability* (is it on the schema the model sees?). It is always pushed into
  the schema and it is eviction-protected, so it is always reachable — it simply
  never needs recovery, because it can never be evicted. Excluding it while
  keeping `notify_user` (identical in both respects) was one predicate answered
  two ways, i.e. the very R1 this card exists to remove.
- **The requirement-action evidence set is derived, not re-typed.** `agent.ts` used
  to carry a free-floating `REQ_ACTION_TOOLS = [...]` literal inside the tool loop.
  That set answers a *different* question from the whitelist — "did this turn
  actually do something?" rather than "must this tool stay reachable?" — so merging
  them would be wrong in both directions (`task_update` is reachable but proves no
  action; a requirement status write proves action but is scenario-gated). It now
  lives next to the whitelist as `REQUIREMENT_ACTION_EVIDENCE_TOOLS`, with the
  overlapping names (`notify_user`, `request_user_input`, `task_create`) **derived**
  from `ACTION_TOOL_GROUPS` — a new human-channel tool cannot be added to one list
  and forgotten in the other. One test pins the resulting membership so a silent
  re-scoping goes red.
- **`reflex` is excluded** from forced action-tool selection on purpose (heartbeat
  patrol carries no work entity). `check_mailbox` is already in the reflex allowlist.
- **Test doubles**: the assembly assertion is skipped when the Agent class is
  replaced wholesale (no registry). Production always observes a real Agent, and
  ids that are merely missing are never skipped.

## 6. Files

- `packages/core/src/capability-packs.ts` — `ACTION_TOOL_GROUPS` / `ACTION_TOOL_IDS`,

## 7. Rollback

`MARKUS_ACTION_TOOL_GUARD=0` restores the previous face without a deploy of code
changes; deleting the branch restores it entirely.
