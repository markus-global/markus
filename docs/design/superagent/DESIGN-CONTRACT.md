## 1. 硬约束（违反任何一条就停下来重想）

### H1–H5（设计 01 §7.1）

| # | 约束 | 判据 |
|---|---|---|
| H1 | **不新增一个「系统」**：新概念必须是现有东西的命名化与归一化 | 若需要同时维护两套，就是新增了系统 → 停 |
| H2 | **加实例 = 注册一个适配器**，不改调度核心 | 新增一个来源只允许加注册项 |
| H3 | **Agent 的语义不能被平台改写**：只做归一化、排序、可观测 | 平台代码里出现「改写正文」即违规 |
| H4 | **人类消息永远优先**：新增节点不得让人等它 | 见 I6，是上线门禁 |
| H5 | **缓存友好**：注入内容尾部可变、头部固定 | 不得因「这批有几个事件」改变 prompt 形状 |

### H6–H9（设计 02 §1.3 / §1.4）

| # | 约束 | 判据 |
|---|---|---|
| H6 | **人的消息永不排在机器后面**：`chat/direct` 不过 gate、不等 router | 构造长评估 + 投 chat，P95 延迟不得劣化 |
| H7 | **一个事实一个写者**：流键只能由 `resolveThreadRefs` 产出 | 别处再推一次 ref 即违规 |
| H8 | **平台不改写正文**：合并只产出引用列表 | `payload.content` 保持原样 |
| H9 | **只做加法**：新增表/列/路径，不重命名、不删除、不改语义 | 本需求的例外见 §5 |

> **H9 与「删机制」的张力**：H9 是**发布兼容**约束，不是「永远不许删」。本需求处理的
> `thread_events` 已确认**从未发布**（`main` 0 处引用），所以删除不违反 H9 —— 判据是「有没有旧用户数据」。

## 2. 第一性原理：四个问题（设计 01 §2）

任何 agent 平台只回答四个问题，回答错了后果明确：

| # | 问题 | 答错的后果 | 本需求哪张卡在修 |
|---|---|---|---|
| **Q1** | 一个外部事件，该不该变成工作？ | 噪音 or 漏做 | 任务五（Eval 两段） |
| **Q2** | 这份工作属于哪条上下文？ | 上下文割裂 or 串味 | 任务一（命名）、任务七（视角） |
| **Q3** | 谁有权做、做到哪一步？ | 越权、不可追责 | 任务六（两种授权不可互替） |
| **Q4** | 人的注意力该被花在哪里？ | 平台变成噪音源 | 任务二（状态词）、任务七（入口） |

**Q4 的可执行推论**：**删除不赚回注意力的东西**。任何新增面板元素必须回答「它赚回了什么注意力」。

## 3. 奥卡姆判据（设计 01 §7.9）

> **硬编码只有两种合法身份**：
> 1. **编译器或数据库能替你守的**（闭集 + 唯一约束 + 单一派生函数）；
> 2. **产品语义本身**（注意力模型、授权档位）。

不满足这两条的枚举/字面量/开关，**一律删掉，不加守卫**。
判据：**改完代码应该变少，不是变多。**

## 4. 不变量（设计 02 §2.3，必须写成行为测试）

| # | 不变量 | 证伪方式 |
|---|---|---|
| I1 | 一个 `ref` 只有一条 thread | 并发 upsert 100 次，断言 count=1 |
| I2 | 同一 thread 同时刻只有一个回合 | 并发投 20 条，断言 `startedAt` 不重叠 |
| I3 | 同一 `idempotencyKey` 只产生一个 disposition | 重投 50 次，行数=1 |
| I4 | `disposition.reason` 永远非空 | 构造所有 action 断言非空 |
| I5 | **直通不改变授权** | 已订阅 thread 上的越权请求仍被拒 |
| I6 | 人的消息不会被 router 延迟 | 长评估期间投 chat，P95 不劣化 |
| I7 | `deriveStage` 对任意事实集恰有一个值 | 穷举 7 个布尔组合（64 种） |
| I8 | 同一资源只能有一个 L3 责任人 | 并发绑两个 admin，第二个被拒 + 可行动提示 |
| I9 | 升级不改旧表任何一行 | 升级前后全表 dump 哈希一致 |

## 5. Gate 六条（设计 02 §3.3，任务五必须逐条对齐）

```
1. 幂等命中                                  → 丢弃（记录 duplicated）
2. addressing ∈ {direct, mention} 且 actor 是人 → dispatch（人已指定，不研判）
3. 命中已订阅 thread                          → 直通（不产生 Decision）
4. 带 tsk_/req_/cs_ id 或资源键               → attach
5. bot/CI 事件 + thread 已结束                → 只记录，不唤醒
6. 其余                                       → needs-assessment
```

两个实测踩出来的细节，不得回退：`mention` 必须算 explicit；sessionId 必须读 `payload.extra.sessionId`
与 `metadata.sessionId` **两处**。

| # | 根因 | 一句话判据 |
