## 一、为什么是这四件事（不是别的）

| 现状证据 | 后果 | 对应动作 |
|---|---|---|
| `ingest()` 仅 2 个 webhook 调用者；`agent.ts` 零处 `threadId` | 主链路不产生 thread 事件 | 卡 3 主干接线 |
| `thread_subscriptions = 0`，`dispositions = 3` | 通路 B 一次都没跑过 | 卡 4 通路 B 实跑 |
| H7 历史引用 `resolveThreadRefs`（历史符号，src 中不存在；卡 1 已改为 `ensureThread`） | 契约指向空气，下一个人找不到唯一写者 | 卡 1 契约勘误 |
| `/api/threads` 与概览 UI 各自排序 | 同一事实两个写者 | 卡 2 排序单源 |
| §0.5 八项端到端验收全「待验」，台账已写「已完成」 | 台账不可信 | 卡 5 验收收口 |

明确不做（本轮）：专用适配器（GitHub/飞书/小红书，缺真实样本）、`rest` 主动 loop、Assignment/Subscription/Policy-accept 三项范围外机制。

## 二、任务 DAG（5 张卡，4 条依赖边）

```
卡1 契约勘误(H7 写者 + 台账纪律) ──┐
                                  ├─→ 卡3 主干接线(chat/task/a2a → ensureThread) ──┬─→ 卡4 通路B 实跑(订阅命中→直通)
卡2 排序单一写者(server/UI 共用一个函数) ─┘                                              └─→ 卡5 §0.5 八项验收 + 台账收口 ←─ 卡2
```

| 卡 | 标题 | 依赖 | 交付判据（可机械判定） |
|---|---|---|---|
| 1 | 契约勘误：H7 写者更正 + 台账纪律写入 | 无 | `grep resolveThreadRefs` 在契约中为 0 命中（历史说明须显式标「历史」）；契约写 `ensureThread` 并注明所在文件:行 |
| 2 | 待办排序单一事实源 | 无 | 新增 1 个排序函数，`grep` 该排序逻辑只有 1 处定义；API 返回序与 UI 首屏序**逐条相等**（脚本断言） |
| 3 | 主干接线：chat/task/a2a 走 `ensureThread` | 卡1 | 新会话产生 thread 行（真实库计数增长）；`recordThreadEvent` 有非 webhook 调用者；行为测试能咬人（改坏必红） |
| 4 | 通路 B 实跑：订阅命中 → 直通 | 卡3 | 真实库 `thread_subscriptions > 0` 且至少 1 次 dispatch 命中记录；无命中时如实标「零流量」 |
| 5 | §0.5 八项端到端验收 + 台账收口 | 卡2、卡3、卡4 | 8 项每项附命令+输出；台账 §9 状态改由验收证据决定 |

并行度：卡1、卡2 可同时开工；卡3 等卡1；卡4 等卡3；卡5 等三方。

## 三、Checklist（每张卡通用 + 专属）

### 通用 DoD（任一不满足即不算完成）
- [ ] 文档 / 代码 / 测试**三者同批**更新（契约改动必须同批落文档）
- [ ] 测试先红后绿（提交里能看出这条断言曾经红）
- [ ] `npm run check:design-ledger` 通过
- [ ] `npx tsc --noEmit` 通过（至少改动包）
- [ ] 相关测试全绿（列命令与条数）
- [ ] 真实库/真实流量取证（不许只用夹具）
- [ ] 悬空引用 / 过时注释 / 临时探针同批清理
- [ ] 提交信息点名残余与未做项

### 卡专属
- 卡1：3 份文档同步（01/02/03 中引用 H7 的位置）＋ 台账 §0.4 判据纪律一条
- 卡2：为排序写一条「同一语义两个定义即红」的 guard 规则
- 卡3：`agent.ts` 三个入口逐一验证；失败时不得静默降级（拒绝 + 可行动提示）
- 卡4：样本来源必须真实，缺样本就写缺，不造夹具
- 卡5：8 项逐条命令 + 输出；不通过的项写「不通过」，不改判据

## 四、行为准则（这一轮我要守的 10 条）

1. **不自行合并、不自行发版**。PR 为止；合并 main / 打 tag / publish 先发消息请示 Owner。
2. **先文档 → 先写测试（看它红）→ 重构 → 验证**。跳步即返工。
3. **单一事实源**：任何排序 / 计数 / 常量 / 不变量只允许一个写者；发现第二个就当场合并，不许"先留着"。
4. **修根因不打补丁**：同一 bug 若能换个记号再犯，说明改错了地方。
5. **证据高于推理**：真实库、真实会话、真实浏览器；夹具只做补充，不做证据。
6. **夹具会撒谎**：数值异常先当 bug，不先当"测试过期"。
7. **不留技术债**：改到哪儿还到哪儿；悬空引用比没有引用更坏。
8. **不猜外部契约**：缺样本（如 webhook payload）就标注"待样本"，不凭猜写代码。
9. **诚实交付**：残余、flaky、未做项逐条列出；台账状态只由验收证据改，不由"我做完了"改。
10. **阻塞 30 分钟内上报**；会话外 `task_submit_review` 必须显式传 `task_id`。

## 五、风险与取舍

| 风险 | 影响 | 缓解 |
|---|---|---|
| 卡3 动 `agent.ts` 主链路，影响所有会话 | 高 | 单次提交可回滚；先加埋点（只记录不改行为）再切换开关 |
| 卡4 仍可能零流量 | 中 | 判据允许「零流量 + 已取证说明」，不硬造数据 |
| 卡2 排序单源可能改变现有 UI 顺序 | 低 | 以 API 序为准，UI 跟随；变更点写进 PR 说明 |
| 卡5 会暴露已有卡"未真完成" | 中 | 正是目的：让台账可信，不粉饰 |
